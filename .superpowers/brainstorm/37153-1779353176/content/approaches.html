Three architecture approaches

How to handle the map across Expo native + web — the main technical split in this project.

A

Web-first PWA (Recommended)

Expo Router handles all navigation. Map = react-leaflet on web (full interactive). On Expo Go native, the map screen uses a WebView that loads the same Leaflet map. Stats cards and sidebar are React Native components on both platforms. Fastest for hackathon — one map implementation, everything else is shared.

Pros

  • One map codebase
  • OpenStreetMap dark tiles work perfectly
  • Fast to build

Cons

  • Native map is a WebView, not truly native gestures
B

Cross-platform conditional maps

Split map component: react-leaflet on web, react-native-maps with OSM tiles on iOS/Android. All other UI (sidebar, cards, dashboard) shared via Expo Router. Truly native map gestures on phone.

Pros

  • Native map performance on phone
  • Best mobile UX

Cons

  • Two map implementations to maintain
  • react-native-maps needs EAS build (not Expo Go)
C

MapLibre unified (same engine everywhere)

@maplibre/maplibre-react-native on native + maplibre-gl-js on web. Same map engine, same tile source, same styling language. Most consistent look across platforms.

Pros

  • Pixel-perfect consistency
  • Custom dark vector tiles

Cons

  • Needs EAS build (not Expo Go)
  • More setup time
