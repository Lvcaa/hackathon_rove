# CommuteSync API — Endpoint Design

**Date:** 2026-05-21
**Project:** CommuteSync (Hackathon Rove — Campionato Universitario AI 2026)

## Context

CommuteSync orchestrates end-to-end urban commutes for citizens of Rovereto. The backend resolves a free-text destination, finds the optimal parking zone + last-mile sharing vehicle, and books both atomically — producing a boarding-pass-style itinerary.

## Key Decisions

| Decision | Choice | Reason |
|---|---|---|
| Booking flow | Two-phase (search → book) | Frontend shows options before locking resources |
| Destination resolution | Fuzzy match against known POIs | No external API, works offline, bounded city dataset |
| Booking persistence | SQLite | Persists between restarts, minimal setup for hackathon |
| Sensor model | Simulated via HTTP endpoint | Mirrors real IoT interface, manually callable for demo |

## Data Sources

- `dataset/zone_parcheggio.csv` — parking zones (polygons, CRS: EPSG:25832)
- `dataset/car_sharing.csv` — sharing vehicle points (CRS: EPSG:25832)
- `dataset/stazioni.csv` — train stations (destination POIs, CRS: EPSG:25832)
- `dataset/taxi.csv` — taxi points (future use)

> **Note:** All datasets use projected coordinates (EPSG:25832). On ingest, centroids are converted to WGS84 (lat/lng) using `pyproj` for API responses and distance calculations.

## Section 1 — Core Trip Flow

### `POST /trips/search`

Resolves free-text destination, finds best parking + sharing combinations, returns ranked itinerary options.

**Request:**
```json
{
  "destination": "Stazione FS Rovereto",
  "user_location": { "lat": 45.891, "lng": 11.035 }
}
```

**Response:**
```json
{
  "destination": { "name": "FS - Trento", "lat": 45.8906, "lng": 11.0353 },
  "options": [
    {
      "option_id": "opt_1",
      "parking": { "id": "P01", "name": "Seconda corona blu", "available_spots": 8, "distance_m": 320 },
      "sharing": { "id": "S04", "type": "car", "address": "via Soteri", "distance_from_parking_m": 150 },
      "route_summary": "320m a piedi → parcheggio → 150m a piedi → auto sharing → 1.2km",
      "estimated_minutes": 12
    }
  ]
}
```

---

### `POST /trips/book`

Atomically reserves the selected parking spot and sharing vehicle. Fails if either resource became unavailable.

`option_id` values are generated by `/trips/search` and cached server-side for 5 minutes (in-memory dict). The book call looks up the cached option to validate it's still valid before committing to SQLite.

**Request:**
```json
{
  "option_id": "opt_1"
}
```

**Response:**
```json
{
  "trip_id": "TRP-20260521-001",
  "status": "confirmed",
  "boarding_pass": {
    "steps": [
      { "step": 1, "action": "Parcheggia in Seconda corona blu", "time": "08:15", "detail": "Stallo libero disponibile" },
      { "step": 2, "action": "Sblocca auto sharing — via Soteri", "time": "08:18", "detail": "150m dal parcheggio" },
      { "step": 3, "action": "Arrivo a Stazione FS Rovereto", "time": "08:27", "detail": "1.2km" }
    ]
  }
}
```

---

### `GET /trips/{trip_id}`

Returns the full boarding pass for an existing booking.

---

### `DELETE /trips/{trip_id}`

Cancels a booking and releases both reserved resources.

## Section 2 — Resource Discovery

### `GET /destinations/search?q={text}`

Fuzzy-matches the query against known POIs (stations from `stazioni.csv`). Uses `difflib.get_close_matches` or `rapidfuzz`.

**Response:**
```json
{
  "results": [
    { "id": "D01", "name": "FS - Trento", "type": "station", "lat": 45.8906, "lng": 11.0353 }
  ]
}
```

---

### `GET /parking`

Lists all parking zones with current availability (from sensor state + admin capacity).

**Response:**
```json
{
  "zones": [
    { "id": "P01", "name": "Seconda corona blu", "max_capacity": 20, "available_spots": 8, "status": "ok" }
  ]
}
```

`status` values: `ok` | `low` (< 20% free) | `full`

---

### `GET /parking/{parking_id}`

Full detail for one zone including geometry centroid and booking history count.

---

### `GET /sharing`

Lists all sharing points with current availability.

**Response:**
```json
{
  "points": [
    { "id": "S04", "address": "via Soteri", "type": "car", "available": true }
  ]
}
```

---

## Section 3 — Sensor & Admin

### `GET /admin/parking`

Lists all zones with their configured capacity. Used by the admin dashboard table.

---

### `PUT /admin/parking/{parking_id}/capacity`

Admin sets the maximum capacity for a zone once. Sensors update availability against this baseline.

**Request:**
```json
{ "max_capacity": 20 }
```

---

### `GET /admin/dashboard`

Aggregated stats for the heatmap panel. Returns all zones with occupancy % and distress flag.

**Response:**
```json
{
  "zones": [
    {
      "id": "P01", "name": "Seconda corona blu",
      "max_capacity": 20, "available_spots": 3,
      "occupancy_pct": 85, "distress": true
    }
  ],
  "summary": { "total_zones": 12, "distressed": 2, "full": 1 }
}
```

---

### `POST /sensors/parking/{parking_id}`

Simulates an IoT sensor reporting current availability. In production, a real sensor would call this endpoint. For the demo, call it manually or via a script.

**Request:**
```json
{ "available_spots": 3 }
```

**Validation:** `available_spots` must be between 0 and `max_capacity`. Returns 400 if capacity not yet configured for this zone.

## Data Model (SQLite)

```
parking_zones     id, name, geometry_wkt, centroid_lat, centroid_lng, max_capacity, available_spots, updated_at
sharing_points    id, address, type, lat, lng, available
destinations      id, name, type, lat, lng
trips             id, destination_id, parking_id, sharing_id, status, created_at
trip_steps        id, trip_id, step_order, action, detail, estimated_time
search_cache      option_id, payload_json, expires_at   -- in-memory only, not persisted
```

---

## Error Handling

| Code | Scenario |
|---|---|
| 404 | Destination not found in fuzzy match |
| 409 | Resource became unavailable between search and book |
| 400 | Sensor reports spots > max_capacity |
| 422 | Missing required fields |

---

## Out of Scope (this spec)

- Authentication / admin login
- Real geocoding (Nominatim)
- Bike sharing dataset (only car sharing available)
- Re-routing / failover logic (described in overview, future phase)
